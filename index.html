01 · WHAT LOOOP DOES

From an idea
to a verified app.

Looop turns a plain-language request into a constrained build, checks the real workspace, and uses every failure as the next repair instruction.

VERIFICATION PIPELINE

One instruction enters. A proven workspace leaves.

  1. 01INPUT
    ✦

    Describe it

    Explain the app, feature, or change you need in normal language.

    • Capture the product goal
    • Define scope and acceptance checks
    OUTPUTStructured build intent
  2. 02FOUNDATION
    ⌘

    Build it

    Looop starts from a known-good blueprint instead of an empty folder.

    • Materialize tested project structure
    • Write only inside marked safe slots
    OUTPUTRunnable workspace
  3. 03ORACLE
    ✓

    Verify it

    Independent tools inspect the actual files and working behavior.

    • Run typecheck and unit tests
    • Exercise real browser journeys
    OUTPUTPass or fail evidence
  4. 04LOOP
    ↻

    Repair it

    Exact failures guide the next attempt—without hiding the evidence.

    • Repair from the failed checks
    • Detect stalls and repeated failures
    OUTPUTConverged or stopped safely

04 · WHY IT IS DIFFERENT

The model builds.
The oracle decides.

Creation and judgment are separate. The model can write code, but only real checks can declare it finished.

BUILT AROUND INDEPENDENT JUDGMENT

The builder never marks its own work complete.

DecisionTypical AI builderLooop
Definition of doneOutput looks plausible✓ Every blocking check passes
Who verifiesThe same model✓ Real tools, no model call

THE LOOOP MODEL

Creation and judgment stay separate.

The model creates and repairs. The oracle runs deterministic checks against the real workspace. The controller decides whether to finish, repair, or stop.

  • No model calls inside verify()
  • Evidence survives every attempt
  • Blocking checks control completion
